# 示范采集准备：统一场景、现有相机校验、录制器

所有正式运行仍经过 `scripts/run_taskb.sh` → `scripts/play_taskb.py` → `TaskBEnvCfg`。录制和相机校验使用同一 v3 篮子机器人、18 个任务物体、区域计分与异常终止条件。独立 MuJoCo 篮子试验的布局和轨迹不作为正式场景或示范数据。

本阶段提供采集基础设施。默认 `demo.solution:AlgSolution` 仍然只是现有零速度站立／收臂模板，没有新增抓取、导航、遥操作或训练功能。

## 先校验现有相机

在已安装项目的 Isaac 环境、工程根目录执行；每次使用新的输出目录：

```bash
bash scripts/run_taskb.sh --headless --enable_cameras --seed 42 --steps 250 \
  --camera-check runs/camera_check_seed42_001
```

相机挂载、旋转、640×480 分辨率、0.1 秒目标更新周期和原有镜头参数集中在 `taskb_student/sensor_contract.py`，由正式场景直接引用。没有新增相机或改动原有视角。

输出包含 `camera_check.json`、两组 RGB PNG、深度预览 PNG 和 `camera_observations.npz`。检查尺寸、K 与现有光学配置是否一致、RGB 是否非全黑、深度是否存在有限有效值。原始光轴深度以米保存；无效深度保持原样。深度预览仅用 0.05–5 m 的灰度显示，不能拿 PNG 当作原始深度。

`data_checks_passed_geometry_unverified` 表示输出检查通过，仍需查看两组 RGB 和深度，核对朝向、遮挡、抓取工作区可见性及深度与图像边缘的一致性。它不表示外参、深度精度或随动已完成标定。`not_ready` 会让启动命令失败，须先检查报告。静态画面重复本身不能证明传感器失效。

## 检查录制链路

```bash
bash scripts/run_taskb.sh --headless --enable_cameras --seed 42 --steps 250 \
  --record-dir runs/recording_smoke_seed42_001
python scripts/inspect_recording.py runs/recording_smoke_seed42_001
```

这段默认是站立链路检查，`source_kind=smoke`，不是成功抓取示范。录制自动附带 `camera_check/`，不必另外指定相机校验目录。没有实际运行 Isaac 前，不能认为相机实测或录制验收已通过。

## 接入示范控制器

已有示范控制器可以放在 `demo/`，例如 `demo/my_demonstrator.py` 中的 `AlgSolution`，并实现与现有模板相同的接口：

```python
class AlgSolution:
    def __init__(self, command=(0.0, 0.0, 0.0)):
        ...

    def reset(self):
        ...

    def predicts(self, obs, current_score):
        return {"action": targets_19, "giveup": False}
```

```bash
bash scripts/run_taskb.sh --enable_cameras --seed 42 \
  --solution demo.my_demonstrator:AlgSolution --record-kind demonstration \
  --record-dir runs/demo_seed42_001
python scripts/inspect_recording.py runs/demo_seed42_001
```

示例中的自定义控制器文件需要另行提供。`demonstration` 只是采集意图标签；每条记录仍标记 `demonstration_success=unreviewed`，需要人工审查质量。控制器只能使用规定 `obs` 和 `current_score`，不得读取场景或物理接口的物体真实位姿。

## 数据契约与时间对齐

每个新目录对应一次 episode，不覆盖已有输出。`manifest.json` 保存 seed、关节顺序、原有相机安装配置、实际源文件／资源哈希、运行库版本、结束原因与分块哈希。配置记录是仿真定义，不是实机外参标定结果。

`chunk_000000.npz` 等默认每 10 个控制步落盘；可用 `--record-chunk-steps` 调整。数据保留环境批维度：例如 `action` 为 `(T,1,19)`，`obs/image/head_rgb` 为 `(T,1,480,640,3)`，标量时间／反馈为 `(T,)`。

| 数据 | 内容 |
| --- | --- |
| `obs/proprio/*` | 规定的机身速度、重力投影、wxyz 姿态、19 关节位置／速度 |
| `obs/lidar/*` | `ranges`、`points`、`hit_mask`、`ready` |
| `obs/image/*` | 前视／腕部 RGB、光轴深度、K |
| `action` | 经过正式入口限位、实际传入 `env.step()` 的 19 维绝对关节角目标，单位 rad |
| `step`、`sim_time`、`wall_time` | 从零开始的动作前步号、仿真时间、经过的单调真实时间 |
| `score_before` | 该次 `predicts()` 收到的得分 |
| `reward`、`score_after`、`terminated`、`truncated` | 对应动作执行后的反馈，得分增量为 `reward / 0.02` |

观测在调用 `predicts()` 和 `env.step()` 前复制，防止仿真复用缓冲区造成错帧。每行含动作前观测与该动作反馈；不保存 `next_obs`，因为 Isaac 的终止步会自动重置，返回的观测不能直接当作终止画面。该行为见 [Isaac Lab v2.2.1 的 ManagerBasedRLEnv 实现](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/envs/manager_based_rl_env.py)。终止后不在同一目录追加新 episode。

控制为 50 Hz，现有相机目标更新率为 10 Hz，因此保留重复图像是正常的。规定观测没有相机曝光时间或帧号，录制器不伪造这些信息，也不保证不同传感器在同一曝光时刻采样。写盘会影响真实运行速度，仿真时间继续按 0.02 s 的控制步计算。初始未就绪传感器样本会原样保留，按 `ready` 和深度有效性过滤。

录制白名单不保存物体真值、物体标签、全局俯视图或教师诊断。不要用 `--diagnostics` 产生的教师状态跟踪文件作为训练输入。

正常结束、给出 `giveup` 或 Python 异常退出时，保存已完成步及最后不足一块的数据；尚无动作反馈的 pending 步丢弃并标记。强制杀进程／断电只能保证此前已写完的块；`status=recording` 表示未干净结束。磁盘写入失败会报错，不会声称保存成功。

读回脚本检查块哈希、白名单、尺寸、步号／时间、动作限位、反馈对齐及 episode 边界。离线文件检查通过不证明物理轨迹有效或示范成功。
