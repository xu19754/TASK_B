# 篮子姿态与倾倒交互分析

双击项目根目录的 **[打开篮子交互仿真.command](../../打开篮子交互仿真.command)**。这是本地 MuJoCo 窗口，不需要 Isaac Sim 或 NVIDIA 显卡。独立依赖安装在 `.venv-basket/`，不会替换正式 Isaac 环境。

它用于观察现有篮子为什么滞留物体、哪些姿态碰到限制，以及修改结构前需要考虑什么。**机器人由程序规定姿态，只有货物参与自由动力学；不是靠关节电机和足底反力站立的整机仿真。** 画面中的机器人不倒，并不能证明真实控制器可以这样站稳。

## 先这样操作

1. 初始装载是糖盒、芥末瓶、香蕉各一件。先让它们静置约 2 秒仿真时间。
2. 点击“整机视角”，再点击“后倾 20°”，观察腿部与机身怎样变化。工具会缓慢移动至目标；左下显示实际角度，滑块显示目标角度。
3. 点击“篮子特写”或“侧面观察”，保持“透明篮子”，观察货物移向弧面后停留的位置。继续保持数秒，查看“尾部排出 0/3”是否变化。
4. 再试“后倾 25°”。自动配姿可能先后移机身，再增加后倾，以避开关节余量不足的中间姿态。
5. 把角度滑到 30°、35°，查看拒绝原因。请求被拒绝时，滑块和机器人保留上一个有效目标；不会把机器人强行摆到超限姿态。
6. 点击“回正并重新装载”，更换摩擦系数或装载方案再试。对照试验都从回正、静置后开始，便于比较。

“仿真时间”可能慢于墙上时间，以界面显示为准。鼠标左键在三维区域拖动旋转视角，右键拖动平移，滚轮缩放；空格暂停/继续，`R` 回正并重装，`S` 保存。

“尾部排出”指物体的整个源网格都曾越过篮子局部坐标 `X < -0.145 m` 的后方判定平面，结果会累计到重新装载为止；它不验证物体经过哪个开口，也不等于进入目标桶。“篮内”按原截面与侧壁几何检查，允许 3 mm 误差。

## 各个控制的意义

| 控制 | 效果 |
| --- | --- |
| 机身后倾 | 正值表示抬头、尾部下降，弧形出口朝后；不是篮子单独转动 |
| 高度、前后平移 | 改变机身位置，四个脚球中心保持初始世界位置，通过腿部逆运动学配姿 |
| 自动匹配 | 调后倾时，在原分析范围内搜索可用高度/前后位置；手动调高度或位置仍进行限制检查 |
| 出口 ≥ 桶沿 + 余量 | 默认启用：后篮沿必须至少 57 cm 高。关闭仅用于研究低位卸料；55 cm 桶沿依然显示，不代表能倒进目标桶 |
| 摩擦 μ | 0.05–1.0 的敏感性试验假设，同时作用于接触几何；不是已测得的塑料摩擦值，也不写入正式环境 |
| 装载方案 | 混合三件、三个糖盒、三个瓶子、三根香蕉；切换时回正并重新装载 |
| 透明篮子 | 只改变显示透明度，原来的 16 块碰撞体持续生效 |
| 显示碰撞体 | 查看底板、前壁、侧壁和弧面分段；不会以一个大矩形填满篮内空间 |
| 保存 | 将当前画面 PNG 和参数 JSON 保存到本目录的 `interactive_runs/` |

青色短线只是 **55 cm 桶沿高度的参考标记**，没有碰撞，不是任务中的目标桶。此诊断场景没有评分、导航或倒入桶的成功判断。

## 哪些约束来自文件，哪些是筛查假设

来自当前 `b2z1_0815_with_basket.urdf` 的数据：

- 机器人所有 link 的几何、安装变换、惯性与质量；零质量 IMU 标记仅作为无质量坐标系加载。
- 原有 19 个可控关节的角度下限、上限和速度上限。界面通过原 URDF 的腿链计算 19 维目标，机械臂固定在原收拢姿态。每个移动步长检查位置与速度范围。
- 篮子固定在 `base` 后上方，质量 0.2 kg，实际壳体惯性和 16 块碰撞体。没有新增篮子转轴或电机。
- 每种货物使用项目 USD 导出的实际网格，碰撞近似为凸包，各 0.5 kg；平动/转动阻尼近似 2/s、4/s。

额外的保守筛查假设，与上一份几何报告一致：四个脚球中心固定、关节离限位至少 2°、机身/髋/大腿离地至少 1 cm、估算质心投影离支持边界至少 2 cm。启用桶沿条件时，出口至少高于 55 cm 桶沿 2 cm。搜索机身 X 在 ±15 cm、高度在 30–65 cm，间距 2.5 mm；界面后倾请求范围为 0–40°。

质心筛查按货物总计 1.5 kg、篮内固定点 `(-0.10, 0, 0.075) m` 估算。实时货物的移动没有反馈到机器人支撑力。无可用搜索结果只说明此固定四足与扫描范围下没找到姿态，不能当作所有动作都不可能的证明。

**尚未验证的限制：电机力矩/功率、足底反力与摩擦锥、足底滑移、闭环姿态控制和动态平衡。** 因此不能说本工具已经满足完整动力学限制。MuJoCo 采用 30 个规定姿态的 mocap link 表达机器人，19 维关节角在外部计算并检查；货物有三个自由刚体。mocap 运动不提供完整的运动速度与惯性反馈，只适合这里的缓慢倾斜观察，不能用于评估快速甩动或抛料。[MuJoCo 的 mocap 机制说明](https://mujoco.readthedocs.io/en/stable/XMLreference.html#body-mocap)

机器人其他网格碰撞采用凸包，未复制 Isaac 的凸分解；MuJoCo 与 PhysX 的接触结果不能视为完全等价。原项目默认关闭机器人自碰撞，本工具也不做整机自碰撞筛查。

## 怎样据此改篮子

重点看三个量：货物停下的位置、后篮沿相对低点的高度，以及机械狗还有多少可用后倾余量。当前弧形端一直上翻到 10 cm 高的篮沿；20° 后倾仍可能形成重力低点，物体移向后部后继续被出口挡住。

可以先用“侧面观察 + 透明篮子”保存 20° 和 25° 画面，在 CAD 中考虑降低尾部出口、将最后接近竖直的一段改为较浅的导料坡，并保留运输挡料能力。结构尺寸需要结合这里的物体朝向与卡住位置确定；当前工具保留原始篮子，不包含未经验证的新出口方案。

本次新增脚本、启动器、独立环境与报告；运行 URDF、行走 policy、任务场景、计分与终止逻辑保持不变。重装货物和回正只是此独立诊断的初始化操作，不能复制到正式评价策略作为卸料动作。
